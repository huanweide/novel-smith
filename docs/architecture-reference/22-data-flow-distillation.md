# 数据全生命周期——从读取注入到蒸馏反哺

> 核心问题：每一类数据（角色/伏笔/地点/功法…）是如何被读取、注入到生成上下文、然后从生成结果中反向分析并更新数据库的？
> 关键洞察：蒸馏层不调用大模型 API——正则/NER/关键词/状态对比，1-3秒完成，零 API 消耗。

---

## 总览：数据在三个阶段的流转

```
写前加载（毫秒级）          写作中（流式生成）           写后蒸馏（1-3秒，不调API）
─────────────────          ─────────────────           ──────────────────────────
世界观设定 → 注入提示词 → AI 参考设定写作 → 本地程序扫描正文 → 检测到新地点/新规则
地理地图   → 注入提示词 → AI 正确使用地名 → 本地程序扫描正文 → 自动添加新地点
势力阵营   → 注入提示词 → AI 保持势力特性 → 本地程序扫描正文 → 更新势力关系/状态
货币体系   → 注入提示词 → AI 正确使用货币 → 本地程序扫描正文 → 补充新货币形式
力量体系   → 注入提示词 → AI 遵循境界规则 → 本地程序扫描正文 → 自动更新修为突破
功法体系   → 注入提示词 → AI 使用正确功法 → 本地程序扫描正文 → 自动添加新技能
角色管理   → 注入提示词 → AI 保持角色性格 → 本地程序扫描正文 → 自动创建/更新角色
人物关系   → 注入提示词 → AI 遵循关系设定 → 本地程序扫描正文 → 自动更新关系状态
伏笔管理   → 注入待兑现事项 → AI 回收/埋设伏笔 → 本地程序扫描正文 → 自动更新伏笔状态
情节脉络   → 注入前后文大纲 → AI 遵循主线方向 → 本地程序扫描正文 → 自动更新进度
支线故事   → 注入活跃支线 → AI 推进支线剧情 → 本地程序扫描正文 → 自动更新支线进度
时间线     → 注入历史事件 → AI 维持时间顺序 → 本地程序扫描正文 → 自动添加新事件
已经历事件 → 注入事件列表 → AI 参考已有事件 → 本地程序扫描正文 → 自动关联新事件
```

## 逐模块详解：读→用→析→存

### 1. 世界观设定

**读取与注入：**
```
【当前世界设定】
世界类型：仙侠世界
时代背景：上古神话时代末期，天道崩坏
核心规则：炼气→筑基→金丹→元婴→化神→大乘→渡劫
地理环境：九天十地
特殊元素：灵气浓度因地而异
```

**蒸馏分析（不调 API）：**
- 正文中出现当前世界观没有记录的地理名称 → 自动添加到备注
- 正文中出现新规则/现象（如"秘境中灵气被压制"）→ 记录到备注
- 正文违背已有设定（如筑基期飞行但设定金丹期才能飞）→ 标记"潜在冲突"提醒用户

### 2. 地理地图

**读取与注入：**
```
【地理环境 - 当前章节所在地：青云山】
- 位于东荒南部，海拔三千丈
- 主峰常年云雾缭绕，山顶有青石广场
- 后山有禁地"坠魔渊"
- 山脚下有凡人小镇"青石镇"
```

AI 行为约束：角色在青云山时场景必须有云雾；不能跨空间跳跃；山下必须用"青石镇"。

**蒸馏分析：**
- 正文出现新地点 → 自动创建地理点位
- 正文对已有地点有新描述 → 自动补充到该地点描述

### 3. 势力阵营

**读取与注入：**
```
【势力阵营 - 当前活跃势力】
1. 天剑宗（正道·宗门）——主角师门，掌门重伤，内部权力争斗
2. 血煞教（邪道·宗门）——敌对，暗中渗透天剑宗
```

**蒸馏分析：**
- 新势力出现 → 自动创建
- 势力关系变化 → 更新关系字段
- 势力首领变更 → 更新势力描述

### 4. 货币体系

**读取与注入：**
```
【货币体系】
- 基础货币：灵石（下品/中品/上品/极品）
- 兑换：1极品=100上品=10000中品=1000000下品
- 特殊：功德点（宗门贡献）、战功（军队）
```

AI 不会写出"金币"这种不匹配的货币。

### 5. 力量体系 / 功法体系（最高优先级）

**读取与注入：**
```
【力量体系】
境界序列：炼气→筑基→金丹→元婴→化神→大乘→渡劫

【主角当前状态】
- 修为：筑基中期
- 主修功法：九天星辰诀（天阶下品）
- 已掌握技能：星辰剑气、北斗步法
```

AI 约束：筑基中期能御器飞行但不能元神出窍；"星辰剑气"要有星辰意象；不能突然使用未学功法。

**蒸馏分析——修为突破检测（核心功能）：**

正文中出现 "筑基成功了" → 蒸馏层识别"炼气→筑基突破" → 自动更新主角修为 → 创建时间线事件 → 更新可用技能列表。

**方法论：正则 + 关键词词典，不调 API。**
```
正则：r"(突破|踏入|晋升|达到|结成|碎丹成婴).*?(炼气|筑基|金丹|元婴|化神|大乘|渡劫)"
扫描全文 → 毫秒级完成
```

**功法使用检测：**
正文出现"九天星辰诀" → 检查该功法是否在主角技能列表中 → 是则记录使用次数，否则自动添加。

### 6. 角色管理

**读取与注入：**
```
★ 主角：李尘 | 16岁 | 天剑宗外门弟子 | 筑基中期
  性格：坚毅果敢，重情重义，略有少年意气
  目标：三个月后的内门考核

★ 女主：苏月瑶 | 15岁 | 掌门亲传 | 筑基后期
  性格：清冷寡言，外冷内热
  关系：青梅竹马，暗生情愫
```

**蒸馏分析——角色行为分析：**
正文中角色行为与性格标签对比 → 一致则记录特征强化，偏离则标记潜在 OOC。

**新角色检测：**
正文出现"身穿黑袍的老者从阴影中走出" → NER 本地模型检测到新人名 → 自动创建临时角色"黑袍老者" → 关联特征（黑袍、沙哑声音、对戒指感兴趣）→ 标记待用户确认。

> 💡 解释：NER = Named Entity Recognition（命名实体识别）。使用本地轻量模型（~20MB），不调大模型 API。1万字扫描约0.5秒。

**关系变化检测：**
正文"苏月瑶第一次露出了笑容，轻轻握住了李尘的手" → 蒸馏层检测到关系进展 → 更新关系状态 → 创建时间线事件。

### 7. 伏笔管理（双重注入）

**为什么伏笔在第一层和第三层都加载？**
- 第一层（待兑现事项）：提醒 AI "你欠着读者什么"
- 第三层（实体数据）：提供伏笔的详细数据（状态、优先级、预计回收章节）

**注入格式：**
```
【待回收伏笔（高优先级）】
1. [重要] 戒指藏有上古器灵（第3章埋下）
   - 状态：尚未激活
   - 建议：本章可让戒指"微微发热"作为铺垫

2. [一般] 天剑宗存在叛徒（第5章埋下）
   - 状态：未揭露
   - 建议：可暗示，不宜明写
```

**蒸馏分析——伏笔回收检测：**
正文"戒指突然爆发出耀眼光芒，苍老声音响起'终于等到你了'" → 蒸馏层识别"戒指器灵"伏笔被回收 → 更新伏笔状态为"已回收" → 自动创建新角色"戒灵"。

**新伏笔检测：**
正文"秘境深处的石门上刻着奇怪符文，李尘看了一眼神魂震荡" → 检测到潜在伏笔 → 自动创建伏笔"神秘石门符文"，状态=已埋设。

**方法论：**
```
伏笔埋设信号关键词：["他并不知道", "谁也没有注意到", "冥冥之中", "一个神秘的身影"]
伏笔回收信号关键词：["原来当年", "真相终于大白", "一切都联系起来了"]
纯字符串匹配 → 0.001秒完成
```

### 8. 情节脉络 / 支线故事

**注入格式：**
```
【主线情节脉络 - 当前进度】
📌 第一卷：天剑风云
├─ 第4章：秘境试炼 → ⏳ 当前章节
├─ 第5章：宗门暗流 → 📅 待写
└─ 第6章：血煞来袭 → 📅 待写

【当前活跃支线】
🔄 苏月瑶身世之谜（进度40%）
  - 未揭示：她体内封印着上古凤血
  - 建议：本章可安排秘境力量触发异象
```

**蒸馏分析：**
- 主线进度：正文完成后确认本章是否完成大纲中预设的内容 → 标记完成/部分完成
- 支线进度：正文中"苏月瑶眼瞳浮现浴火凤凰虚影" → 支线进度 40%→55% → 更新角色状态 → 创建时间线事件

### 9. 时间线 / 已经历事件

**注入格式：**
```
【时间线 - 当前故事时间点】
已发生关键事件（按时间顺序）：
① 第1个月：天机阁预言
② 第2个月：入门考核通过
③ 第3个月：戒指激活
...
⑦ 第8个月（现在）：秘境试炼开启
```

AI 约束：不会搞错事件时间顺序；筑基前不能写得太强；提及血煞教时主角有心理阴影（第7个月遇袭过）。

**蒸馏分析：**
正文扫描提取所有可记录事件 → 按重要性分级 → 加入时间线 → 关联角色/地点/物品。

## 蒸馏层为什么这么快？（关键架构洞察）

### 核心答案：蒸馏层不调用大模型 API

| 操作 | 调 API 的做法 | 本地程序做法 | 速度差距 |
|------|-------------|-------------|---------|
| 检测修为突破 | 调大模型理解全文 | 正则匹配 `r"(突破|踏入).*?(筑基|金丹)"` | 3-5秒 vs 0.01秒 |
| 检测新角色 | 调大模型分析人物 | NER 本地模型（~20MB） | 3-5秒 vs 0.5秒 |
| 检测伏笔回收 | 调大模型理解剧情 | 关键词词典匹配 | 3-5秒 vs 0.001秒 |
| 更新时间线 | 调大模型提取事件 | 状态对比 + 规则引擎 | 3-5秒 vs 0.01秒 |
| **总耗时** | **15-25秒 + API额度消耗** | **1-3秒 + 零API消耗** |

### 四遍扫描流程

```
正文生成完成
    ↓
第一遍：实体识别（正则 + NER 本地模型）
  识别人名/地名/物品名/势力名/修为术语 → 毫秒级
    ↓
第二遍：状态变化检测（前后对比）
  "筑基中期"→"筑基后期" = 突破事件 → 毫秒级
    ↓
第三遍：伏笔模式匹配（关键词词典）
  埋设信号/回收信号匹配 → 毫秒级
    ↓
第四遍：一致性校验（规则引擎）
  名字写错/修为写错/关系写错 → 毫秒级
```

### 为什么"笨办法"反而最快

计算机做机械的字符串匹配（Ctrl+F），比让 AI "理解"文本快得多。蒸馏不是"读懂"，而是在文本中找已知模式。这跟编译器解析代码的原理类似——不需要理解代码含义，只需要识别语法结构。

### 唯一调用 API 的环节

```
正文生成 → 调用大模型 API（花钱，花时间）
蒸馏分析 → 本地程序处理（不花钱，1-3秒）
```

## 完整写作实例

假设用户说"写第4章：秘境试炼"：

**写前加载（毫秒级）：**
- 待兑现事项 2条 → 戒指器灵未激活、宗门叛徒未查出
- 主角状态 → 李尘，筑基中期，天剑宗外门弟子
- 分层回顾 → 上一章结尾（获得秘境准入资格）、本卷主线（天剑风云）、全书核心（应劫之人成长）
- 前后大纲 → 第3章已完成、第4章当前、第5章待写
- 事件线 → 7个已发生事件
- 实体数据 → 4角色+2势力+3物品+2伏笔+世界观+地理+力量体系
- 风格设定 → 第三人称

**写作中（流式生成）：** AI 逐字输出到写作面板，用户实时查看。

**写后蒸馏（1-3秒）：**
- 李尘突破筑基后期 → 更新修为
- 苏月瑶凤血觉醒 → 更新角色状态+时间线事件
- 发现上古传送阵 → 创建新地点+新伏笔
- 遇到神秘黑袍人 → 创建新角色（临时名）
- 全部自动写入数据库，用户无需手动操作
