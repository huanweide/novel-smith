# 小说创作平台——完整功能架构与生成引擎

> 整合三份来源：平台功能模块（19模块+58工具）、六步正文生成流程、五步叙事生成引擎
> 两个层次互不矛盾——A 是"平台上有什么"，B 是"生成时怎么做"

---

## A 层：平台功能模块架构

### 总体三层

```
前端界面（写作面板 / 大纲树 / 设定面板 / 关系图）
        ↓ 用户操作
AI Agent 层（理解意图 → 调用工具 → 返回结果）
        ↓ 工具调用
业务逻辑层（查/增/改/删 → 数据持久化）
        ↓ 读写
数据库层（角色表 / 伏笔表 / 章节表 / 世界观表 …）
```

### 19 个业务模块一览

| # | 模块 | 核心数据 | 写作时的作用 |
|---|------|---------|-------------|
| 1 | 🌍 世界观 | 世界名称、类型、时代背景、核心规则、地理、社会结构、历史、特殊元素、主要冲突、势力格局 | 自动注入，保证世界一致性 |
| 2 | 📖 故事核心 | 主题思想、核心冲突、核心悬念 | 记忆注入，不偏离主线 |
| 3 | 🗺️ 地理地图 | 树形层级地点（如九天十地→北原→北原帝坟），parent_id 实现无限层级 | 注入相关地点描述，避免地理矛盾 |
| 4 | 🏰 势力阵营 | 宗门/家族/帝国/帮派，立场（正道/邪道/中立） | 人物出场时注入势力背景 |
| 5 | 💰 货币体系 | 货币种类、汇率、购买力 | 交易场景一致性 |
| 6 | 💎 物品 | 武器/丹药/法宝/材料/功法，稀有度（普通→神话） | 使用物品时注入属性 |
| 7 | ⚔️ 力量体系 | 修炼境界划分（如练气→筑基→金丹→元婴…共17境） | 确定角色战力层级 |
| 8 | 📜 功法体系 | 攻击/防御/辅助/身法/秘术，品阶 | 战斗场景注入功法效果 |
| 9 | ✨ 特殊设定/金手指 | 系统/金手指/血脉/天赋/体质 | 核心记忆注入，不被遗忘 |
| 10 | 📋 大纲 | 卷→章节树形结构，node_type(volume/chapter)，summary | 读取当前章+前后章摘要，保证剧情连贯 |
| 11 | 🧑 角色 | 姓名、类型（主角/配角/反派/龙套）、身份、性别、年龄、简介 | 出场时注入背景，避免人设崩塌 |
| 12 | 🔗 人物关系 | 图结构：角色A↔角色B，关系类型（师徒/父子/敌对/爱慕等） | 对话/互动场景注入关系 |
| 13 | 🔮 伏笔 | 五状态机（未埋设→已埋设→已回收/已废弃），importance（核心/重要/一般） | ⭐自动检测：该埋设/回收时提示 |
| 14 | 📊 情节脉络 | 按幕/阶段划分的主线剧情 | 确保不偏离主线 |
| 15 | 🔄 支线故事 | 状态（未开始/进行中/已完结），关联角色 | 提醒未完结支线需照顾 |
| 16 | ⏱️ 时间线 | 事件类型（主线/角色弧线/闪回/伏笔呼应/关键对话/背景/时间跳跃），关联章节+角色 | 注入前后事件，时间顺序不乱 |
| 17 | 📝 已经历事件 | 角色视角的关键事件记录 | 主角状态档案，避免角色遗忘经历 |
| 18 | 📄 章节正文 | 正文内容+状态 | 核心产出 |
| 19 | 🤖 AI Agent | 58个工具接口，理解指令→调用工具→操作数据 | 用户与数据库之间的智能层 |

### 58 个工具分布（按 CRUD 分类）

- 查询类（读）：25 个
- 创建类（写）：13 个
- 修改类（写）：13 个
- 删除类（删）：7 个
- 完整 CRUD 模块：角色、伏笔、势力、地理、物品、力量体系、功法、特殊设定、大纲、时间线（10个）
- 仅查询模块：人物关系、情节脉络、支线故事、故事核心、货币体系（5个）
- 核心特殊工具：生成章节正文（1个）

## B 层：正文生成流程（六步宏观）

```
用户点击"生成正文"
        ↓
第一步：记忆注入
  ├─ 待兑现事项（之前埋下的钩子/伏笔）
  ├─ 主角状态档案（修为/物品/关系/经历）
  └─ 分层故事回顾（过去N章摘要）
        ↓
第二步：上下文加载
  ├─ 当前章大纲摘要 + 前后章大纲摘要
  ├─ 事件线（最近N章主要事件）
  ├─ 主角事件线
  └─ 支线事件流（活跃支线状态）
        ↓
第三步：实体数据注入
  ├─ 当前章节涉及的所有角色信息
  ├─ 当前章节涉及的所有物品信息
  ├─ 当前章节涉及的所有伏笔状态
  ├─ 当前章节涉及的所有势力信息
  └─ 世界观背景（地理/历史/规则）
        ↓
第四步：AI 生成正文
  ├─ 应用仙侠文风模板
  └─ 流式输出到 AI 写作面板
        ↓
第五步：后处理
  ├─ 润色（优化语句流畅度）
  └─ 一致性检查（检查前后矛盾）
        ↓
第六步：蒸馏入库
  ├─ 自动提取新人物→创建角色
  ├─ 自动提取新物品→创建物品
  ├─ 自动提取新事件→创建时间线事件
  ├─ 自动检测伏笔埋设/回收→更新伏笔状态
  └─ 自动检测突破事件→记录关键节点
        ↓
用户在 AI 写作面板中预览 → 亲自点击「采纳/拒绝/重新生成」
```

> ⚠️ 注意：第六步"蒸馏入库"意味着 AI 生成的内容会自动反哺到数据库中——新角色、新物品、新事件都会被自动提取和创建。

## C 层：叙事生成引擎（五步微观）

> 这是 B 层"第四步 AI 生成正文"内部的 Prompt 工程细节。
> B 层描述的是**平台做了什么**，C 层描述的是**LLM 怎么被引导去写**。
> 两者不矛盾：B 是外层流程，C 是内层 Prompt 架构。

### 上游：三层固定输入源

**第一层：静态项目数据库**（每次对话加载，白名单约束）
| 模块 | 约束规则 |
|------|---------|
| 作品定位 | 不可篡改 |
| 世界观设定 | 禁止自创地名/境界 |
| 力量体系 | 角色等级严格对标，不可升降 |
| 势力阵营 | 每个势力有独立故事线规划 |
| 地图名册 | 严禁自创名单外地点 |
| 角色概览 | 必出场角色不可遗漏 |
| 伏笔表 | 单章 CF 行≤2 条（必须回收类不限） |

> 💡 解释："白名单约束"=AI 只能使用数据库中已存在的地名/境界/角色/物品，禁止自由发挥创造新的。这是防止 AI 写飞的核心机制。

**第二层：当前章节数据包**
```
章节块 = {
  类型: "chapter",
  现有摘要: 字符串/空,          ← 最高优先级故事蓝本
  前后章节上下文: {
    前3章摘要/前2章摘要/前1章摘要,
    前一章实际正文尾段,          ← 最高锚点（衔接自检的依据）
    后一章摘要
  },
  衔接冲突自查: {规则A→D},
  关联数据: {
    出场角色清单, 场景地点, 关联伏笔, 道具物品, 情绪氛围
  }
}
```

> 💡 解释："前一章实际正文尾段"是整个系统最重要的锚点——它决定了本章开头不能跟上一章结尾矛盾。冲突自检器就是围绕这个字段工作的。

**第三层：用户实时输入**
用户在对话中给出的方向修正，标记为 P0 最高优先级。例如"主角决定亲自去对方宗门见见再说"。

### 处理层：五步流水线

#### 第一步：优先级裁决器

规则：P0 > P1 > P2 > P3 > P4，冲突时高优先级覆盖低优先级。

| 层级 | 内容 | 示例 |
|------|------|------|
| P0 | 用户额外要求 | "主角决定亲自去对方宗门" |
| P1 | 现有摘要（本章故事蓝本） | 已写好的本章大纲摘要 |
| P2 | 角色状态/剧情连贯性 | 前一章结尾主角在密室闭目→本章开头不能在演武场 |
| P3 | 事件流七要素 | 欲望→阻碍→行动→结果→意外→转折→结局 |
| P4 | 情节脉络/角色概览/伏笔表 | 史诗定位、伏笔回收节点 |

> 💡 解释：裁决器的核心逻辑是——用户说的 > 大纲写的 > 角色状态约束 > 事件流套路 > 背景设定。P0 可以覆盖 P1，但不能覆盖 P2（物理可行性——人不能在两个地方同时出现）。

#### 第二步：冲突自检器（衔接冲突自查）

触发条件：存在"前一章实际正文尾段"时启动。

四维比对：
1. **空间一致性**：人物是否回到了已离开的场景？
2. **动作一致性**：人物是否在做已完成过的动作？
3. **时刻一致性**：本章首段时刻是否严格晚于前章尾段时刻？
4. **在场人物一致性**：已离场角色是否莫名又出现？

修复规则（A→D，命中即止）：
- **A**：完全不矛盾 → 正常推进
- **B**：时间紧邻差异 → 用一句过渡桥接
- **C**：空间倒退/动作回滚/时刻倒流 → 使用时间跳跃桥接（"次日清晨"）
- **D**：地理硬冲突且无法用跳跃桥接 → 重写章首衔接方位

> 💡 例子：前章尾段主角在密室闭目，本章原摘要在演武场展示战车 → 命中 C → 加桥接："主角在密室中闭目内视片刻后，推门而出，走向演武场"

#### 第三步：叙事生成器（核心引擎）

输入：裁决器输出 + 自检器输出 + 关联数据
输出：符合格式的摘要文本

生成策略（三级）：
1. 有现有摘要 → 以其为主干扩写，事件流降级为补充素材
2. 无现有摘要但有事件流 → 以七要素为骨架
3. 二者皆无 → 按情节脉络和上下文自由设计

写作硬约束（L2 层级，次高优先级）：
- 反多角色平行模板（必须有主次）
- 禁圣母/禁说教
- 段尾硬停（动作段用具象收尾）
- 内省配额（心理活动 ≤20%）
- 信息密度（一般场景 1-3 句，关键场景 3-6 句）
- 修饰词节制（首次可加修饰，后续直接用名词）
- 让行为说话（写完动作不补解释）
- **否定对比式比喻禁令**（绝对禁止"不是 X，是 Y"结构）

> 💡 解释："否定对比式比喻"= "这不像刀，更像一道闪电" 这种句式。它被禁是因为 AI 过度使用这种句式导致文风油腻。这是从 CLUADE.md 里"禁止'不是……而是……'"规则延伸出来的。

#### 第四步：网文叙事铁律校验

摘要生成后逐条检查：

1. **信息不对称制造张力**：读者知道角色不知道 / 角色知道读者不知道 / 角色 A 知道角色 B 不知道
2. **延迟揭示**：每章至少 1 个"提出问题但不在本章回答"的信息点
3. **钩子前置**：开头先抛结果/异常状态，再回溯过程
4. **留白艺术**：对话不说完、场景不写全、动机不点破
5. **章尾制造翻页欲**：用五大钩子类型收尾

五大章尾钩子：
- 身份炸弹（"他缓缓摘下面具——"）
- 认知颠覆（"原来她一直在骗我"）
- 动作定格（刀锋停在颈前半寸）
- 倒计时（还剩三天）
- 信息炸弹（揭一个埋了很久的伏笔）

**绝对禁区**：报告体、全知体、论文体、预告体、日记体。

> 💡 检验标准：读者看完最后一段第一反应是"卧槽？！"/"为什么？！"/"怎么可能？！"——如果是"嗯，然后呢"，则不合格。

#### 第五步：格式组装器

将叙事文本按固定模板输出——三段式 + 独立标记行：

```
【章首衔接】（独占首行，50-120字）
⟨正文叙事段落⟩（600字内）
【章尾悬念】（独占末行：具体画面/动作 + 不可能的事实 + 戛然而止）

R|角色名|身份|标签|行动摘要
L|地点名|描述|类型|等级|所属区域
G|势力名|描述
P|道具名|类型|描述
CF|伏笔名|类型|表现|作用|操作|完成度|优先级|标签|预期回收章节
M|情绪类型|强度|说明
K|"关键台词"
EL|章节标题|摘要
T|起始时间|结束时间|事件类型
```

> 💡 解释：这些标记行是"蒸馏入库"（B 层第六步）的数据来源。AI 在正文末尾输出这些结构化标记，系统解析后自动创建/更新数据库记录。R=角色、L=地点、G=势力、P=道具、CF=伏笔、M=情绪、K=关键台词、EL=事件、T=时间。

## 两层对照：B（宏观流程）vs C（微观引擎）

| B 层步骤 | C 层对应 | 关系 |
|----------|---------|------|
| 第一步：记忆注入 | 上游第一层（静态数据库） | B 描述"注入什么"，C 描述"注入的数据长什么样" |
| 第二步：上下文加载 | 上游第二层（章节数据包）+ 冲突自检器 | B 描述加载哪些上下文，C 描述如何用这些上下文做衔接检测 |
| 第三步：实体数据注入 | 关联数据字段 | 同一件事的不同视角 |
| 第四步：AI 生成正文 | 优先级裁决器 + 叙事生成器 + 铁律校验 | **C 层是 B 层第四步的内部实现** |
| 第五步：后处理 | — | C 层未覆盖（C 聚焦生成，不覆盖后处理） |
| 第六步：蒸馏入库 | 格式组装器（独立标记行） | 标记行是蒸馏入库的数据协议 |

## 设计哲学

一句话：**用分层约束的累加，替代自由生成的发散。**

| 设计点 | 解决的问题 | 效果 |
|--------|------------|------|
| 白名单约束 | AI 自创地名/境界 | 项目数据一致性 |
| 优先级裁决器 | 多源信息冲突 | 自动判定谁覆盖谁 |
| 衔接自检器 | 前后章逻辑断裂 | 时空连贯性 |
| 叙事铁律 | 流水账/报告体/全知体 | 网文阅读体验 |
| 否定对比式禁令 | AI 常见病句式 | 文风干净 |
| 格式模板 | 每次输出结构不一 | 下游可解析+蒸馏入库 |
| 蒸馏入库 | 新实体靠人工手动录入 | 自动化反哺数据库 |
