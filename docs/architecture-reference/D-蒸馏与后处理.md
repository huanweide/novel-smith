# D — 蒸馏与后处理

> 整合自：03-distillation-system + 14-postprocessing-pipeline + 22-data-flow-distillation + 23-core-architecture-patterns（蒸馏部分）
> 边界：只管正文生成后的自动化分析。不涉及生成流程（→B）、不涉及记忆注入（→C）、不涉及规则检查（→E）。
> 核心洞察：蒸馏引擎不调用大模型 API——正则 + NER + 关键词 + 状态对比，1-3 秒完成，零 API 消耗。
> 最后更新：2026-06-17

---

## 1. 八步后处理流水线

用户采纳正文后，蒸馏引擎按顺序执行：

```
第1步：实体检测（正则 + NER 本地模型）
  识别正文中的新人名/新物品名/新地名/新势力名 → 毫秒级

第2步：事件提取
  从正文中提取所有可记录的事件 → 按重要性分级

第3步：突破/转折检测
  检测修为突破、关系转折、重大决策 → 标记为核心事件

第4步：S/A/B/C 四级事件分类
  对提取的事件进行重要性评分和分级

第5步：承诺/伏笔检测
  检测新伏笔埋设 → 检测已有伏笔的回收/深化 → 更新伏笔状态

第6步：角色状态归档
  更新角色的修为/位置/关系/物品/目标

第7步：三层摘要生成
  生成 chapter_summary + key_events + character_states

第8步：伏笔关联
  将新事件与已有伏笔链建立关联
```

**每个步骤都写入对应的数据库表**，不调大模型 API。总耗时 1-3 秒。

---

## 2. 四遍扫描流程

```
正文生成完成
    ↓
第一遍：实体识别（正则 + NER 本地模型，~20MB）
  识别人名/地名/物品名/势力名/修为术语
  工具：正则模式库 + 预定义词典（已知实体列表）
  速度：1 万字约 0.5 秒
    ↓
第二遍：状态变化检测（前后对比）
  "筑基中期"→"筑基后期" = 突破事件
  工具：状态快照对比（生成前 vs 生成后）
  速度：毫秒级
    ↓
第三遍：伏笔模式匹配（关键词词典）
  埋设信号 / 回收信号匹配
  工具：预定义触发词词典
  速度：0.001 秒
    ↓
第四遍：一致性校验（规则引擎）
  名字写错 / 修为写错 / 关系写错
  工具：规则匹配
  速度：毫秒级
```

## 3. 新实体检测——命名模式库

体系的核心是对**中文仙侠命名规则**的领域知识编码：

| 实体类型 | 正则模式 | 示例 |
|---------|---------|------|
| 丹药 | `[一二三四五六七八九十]品[一-鿿]{2,4}丹` | 七品培元丹、三品清心丹 |
| 丹药（无品级） | `(?:还魂\|筑基\|凝气\|培元\|洗髓\|辟谷)[丹丸]` | 筑基丹、洗髓丹 |
| 法宝 | `[一-鿿]{1,3}(?:剑\|刀\|镜\|鼎\|塔\|印\|旗\|幡\|珠\|环\|镯\|簪)` | 青云剑、玄天印 |
| 功法 | `[一-鿿]{2,6}(?:诀\|经\|典\|功\|法\|术\|引\|咒\|拳\|掌\|指\|腿)` | 星辰诀、九天剑法 |
| 地点 | `[一-鿿]{2,4}(?:山脉\|山谷\|峡谷\|城\|镇\|村\|宗\|门\|派\|殿\|阁\|洞\|府\|宫)` | 苍云山脉、落霞城 |
| 材料 | `[一-鿿]{2,4}(?:草\|花\|果\|叶\|根\|藤\|石\|木\|玉\|晶\|矿\|铁\|铜)` | 寒冰草、聚灵石 |

**排除词库（防误报）：**
- 身体部位：拳头、手掌、手臂、膝盖
- 普通名词：桌子、茶杯、纸张
- 抽象名词：办法、想法

## 4. 归属推断——三层策略

| 策略 | 方法 | 置信度 |
|------|------|--------|
| 属格匹配 | `"XX的XX"` — 如"李尘的青锋剑" | 0.95 |
| 动词前置 | `"XX从储物袋中取出XX"` / `"XX掏出XX"` | 0.85 |
| 段落主人推断 | 物品所在段落中频率最高的角色名 | 0.6 |
| 无法推断 | 标记为 `ambiguous`，留待用户确认 | — |

## 5. 消歧——同名不同物

当同一名称在正文中出现多次但指向不同实体时：

```
区分维度：
  特征1：上下文中的角色（"苏月瑶的玉佩" vs "掌柜的玉佩"）
  特征2：修饰词（"手中握着的" vs "柜台里的"）
  特征3：动词（"握紧" vs "标价"）

无法自动消歧 → 标记为 ambiguous → 等用户手动确认
```

## 6. 伏笔检测

### 触发词词典

```
埋设信号：
  "他并不知道" / "谁也没有注意到" / "冥冥之中" / "命运的齿轮"
  "神秘的XX" / "似乎隐藏" / "隐隐不安" / "莫名熟悉"

回收信号：
  "原来" / "真相" / "果然" / "正如" / "终于明白"
  "恍然大悟" / "一切都有了解释" / "原来如此"

深化信号：
  关键词再次出现但无回收标记词 → 默认判定为深化
```

### 新伏笔检测

```
正文中出现：
  1. 触发词（"神秘的XX"）
  2. 且该实体不在已有伏笔的关联关键词中
  3. 且不在已知实体词典中
→ 自动创建新伏笔，状态 = "已埋设"，标记为"待用户确认"
```

## 7. 事件重要性评分——六维权重

| 维度 | 权重 | 逻辑 |
|------|------|------|
| 出现频率 | 最多 50 分 | 出现越多次越重要 |
| 出现位置 | 20-30 分 | 结尾 > 开头 > 中间 |
| 修饰词强度 | 15 分/词 | "神秘""古老""惊天""绝世" |
| 与已有伏笔关联 | 40 分 | 直接关联伏笔的实体最重要 |
| 实体类型权重 | 15-30 分 | 角色 30 > 事件 25 > 物品 20 > 地点 15 |
| 与主角关联度 | 25 分 | 主角相关的优先级高 |

**判定等级：** ≥100 = 核心（S级） / ≥70 = 重要（A级） / ≥40 = 一般（B级） / <40 = 背景（C级）

## 8. 数据反哺——每类数据写入哪些表

| 检测到的变化 | 写入目标 |
|-------------|---------|
| 新角色出现 | characters 表（标记待确认） |
| 修为突破 | character_archives 表 + events 表 + timeline 表 |
| 位置变化 | character_archives 表 |
| 新物品出现 | items 表（标记待确认）+ 推断归属 |
| 物品转移 | items 表更新 owner |
| 伏笔回收 | foreshadows 表状态→已回收 |
| 伏笔深化 | foreshadows 表追加 hint |
| 新伏笔埋设 | foreshadows 表新增 |
| 关系变化 | character_archives.relationships 更新 |
| 新地点出现 | geo_map 表新增 |
| 势力变化 | factions 表更新 |

## 9. 长效记忆衰减

章节数量增长后，低重要性事件自动衰减：

| 重要性 | 保留策略 |
|--------|---------|
| S 级（核心） | 永久保留，全文注入 |
| A 级（重要） | 保留最近 30 章 |
| B 级（一般） | 保留最近 15 章 |
| C 级（背景） | 保留最近 5 章，超期自动清除 |
