# J — 导入与拆书

> 整合自：05-book-splitting
> 边界：只管从外部文件导入已有小说。不涉及在线生成流程。
> 最后更新：2026-06-17

---

## 1. 概述

支持用户导入已有的完整小说（TXT/Word/PDF），自动拆分为章节、提取角色/伏笔/事件/设定，一键生成完整的项目数据库。

---

## 2. 五阶段导入流水线

### 阶段一：预处理

```
原始文件（TXT/Word/PDF）
  → 文本提取（去格式、去乱码）
  → 编码统一（UTF-8）
  → 分段清理（合并断行、去页眉页脚）
```

### 阶段二：章边界检测（三层）

| 层 | 方法 | 处理对象 |
|----|------|---------|
| 第1层 | 正则匹配章节标题（"第X章"/"Chapter X"/"卷一"） | 有明确章节标记的小说 |
| 第2层 | 语义边界检测（LLM 判断内容主题变化点） | 无章节标记但内容有自然分段 |
| 第3层 | 固定字数切割（每 3000-5000 字切一段） | 二者都失败时的回退方案 |

### 阶段三：逐章 LLM 解析

每章调用一次 LLM，提取：
- 章节摘要
- 出场角色及状态
- 关键事件
- 提及物品
- 涉及的伏笔（if any）

### 阶段四：全局跨章蒸馏

所有章节解析完毕后，全局汇总：
```
别名合并：同一角色在不同章节的不同称呼 → 统一
  例："小李" + "李尘" + "李师兄" → 统一为 "李尘"

时间排序：所有事件按章节顺序排列 → 建立全局时间线

伏笔链：跨章追踪同一伏笔从埋设到回收的完整链路
  "第3章提到玉佩异常" → "第5章玉佩发光" → "第10章揭示玉佩是钥匙"
  → 自动构建伏笔状态机
```

### 阶段五：结构化入库

批量创建/更新数据库记录：
```
characters ← 逐章提取 + 别名合并
foreshadows ← 伏笔链构建
events ← 全局时间排序
worldview ← 从内容推断
geo_map ← 出现的地点
outline_nodes ← 章节结构
chapters ← 正文内容
```

## 3. 关键技术挑战

### 别名消歧

```
问题：同一角色在不同章节以不同名字出现
方案：
  1. 构建共现矩阵（哪些名字在同一场景中出现过交互）
  2. 排除法：同在场景中且互动的两个名字 → 不是同一个人
  3. 特征匹配：修为/关系/位置一致 → 可能是同一个人
  4. 用户确认：不确定的合并提交给用户决策
```

### 矛盾检测

```
问题：导入的小说本身有前后矛盾
方案：
  1. 全局扫描后列出所有矛盾点（如"第3章说筑基初期，第5章说筑基后期但中间没有突破描写"）
  2. 标记为"潜在冲突"
  3. 提交给用户手动修正
```
