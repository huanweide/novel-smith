# Token节省策略 — 可支持百万字长篇的技术基础

## 核心原则
| 原则 | 含义 | 对应策略 |
|------|------|----------|
| 不加载不需要的 | 不把全部数据塞进上下文 | 懒加载、分层注入、按需选择字段 |
| 不存储可推导的 | 能用摘要替代就不存原文 | 蒸馏摘要、章节摘要 |
| 不重复已加载的 | 同样的信息只加载一次 | 去重检测、缓存机制 |

## 五种上下文压缩方法

### ① JSON结构化压缩 (节省65-70%)
自然语言→键值对。如角色描述85tokens→28tokens。
所有数据类型一致节省65-70%。

### ② 选择性字段注入 (节省40-77%)
角色13个字段按需加载：
- 主角色: 8-10个字段
- 次角色(1次对话): 3-4个字段 (节省70-77%)
- 背景角色: 1-2个字段 (节省85-92%)

### ③ 增量注入 (节省81%)
只注入变化部分，每10章一次全量刷新。
```
第1章: 500t(全量) → 第2章: 50t(增量) → ... → 第10章: 500t(全量)
平均: 95t/章 vs 全量500t/章 → 节省81%
```

### ④ 引用压缩 (节省85-92%)
用ID替代完整描述: "[C:1]" 替代 "青云宗内门弟子苏月..."

### ⑤ 分段优先级截断 (节省42%)
```
Tier1(必保留): 当前章大纲+前2章结尾+待兑现事项S级
Tier2(优先保留): 主角状态档案+S+A级事件+相关角色
Tier3(可压缩): 世界观摘要+势力关系+力量体系
Tier4(可丢弃): B级事件+已完成支线+长期不变设定
```
超过token预算时从Tier4开始逐级丢弃。

## 分层注入 vs 不分层 (89%节省)
- 47章×65t/事件 = 3055t (不分层)
- S级120t + A级160t + B级摘要50t = 330t (分层)

**章节增长趋势**:
| 章节 | 不分层 | 分层 | 节省率 |
|------|--------|------|--------|
| 10 | 1200 | 400 | 67% |
| 50 | 6000 | 500 | 92% |
| 100 | 12000 | 550 | 95% |

分层: O(1)恒定 → 支持无限章节

## agent_summarize_history (压缩90-94%)
- 触发: 对话超15-20轮 or 上下文超70%
- 方法: 按主题分段→提取意图+结果摘要→丢弃问候/重试/冗余
- 压缩率: 10轮90% | 20轮92% | 30轮93% | 50轮94%
- 保留优先级: 创作决策>写操作>风格偏好>查询交互>寒暄

## 更多技术方法

### 懒加载 (节省90-98%)
只加载当前章涉及的角色/地点/势力，未涉及→不加载。

### 去重检测 (节省15-25%)
多个数据源(事件+档案+突破+时间线)都提同一件事→去重，只保留一次。

### 缓存机制 (节省75%)
首次生成: 加载4000t → 缓存。重生成: 直接用缓存，0额外消耗。

### 提前终止 (节省10-20%)
检测信息熵→连续N个token无新信息→提前终止生成。

## 综合效果
**100章小说**:
- 无优化: 1,900,000 tokens
- 全优化: 600,000 tokens
