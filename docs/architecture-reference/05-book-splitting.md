# 拆书功能 — 将已有小说转化为结构化AI项目

## 定义
拆书 = 将已存在的完整小说(TXT/Word/PDF)导入系统，自动解析出结构化数据（大纲、角色、事件、伏笔、时间线等），使AI能"读懂"全文。

## 解决的问题
| 问题 | 拆书如何解决 |
|------|-------------|
| 冷启动困难 | 一键导入已有文本，自动生成结构化数据 |
| 续写/改编老书 | AI理解全书脉络后可精准续写 |
| 同人/二创 | 提取核心要素后基于此改写 |
| 数据分析 | 结构化的章节/角色/伏笔数据直接可分析 |
| AI辅助修订 | AI拥有全本知识，修订更精准 |

## 五阶段流程

```
输入: 原始小说文本(TXT/Word/PDF)
  ↓
① 预处理: 格式统一→编码检测→噪音过滤→段落合并
  ↓
② 章节边界识别 (3层检测, 准确率95-98%)
  · 正则匹配: 第X章/Chapter X/数字序号 (覆盖70-80%)
  · 结构特征: 空行密度/段落长度突变/时间标记 (覆盖10-15%)
  · LLM语义判断: 模糊边界 (覆盖剩余10-15%)
  ↓
③ 逐章解析(LLM调用): 摘要生成+角色提取+事件提取+地点提取+物品提取+伏笔检测
  ↓
④ 全局蒸馏: 跨章角色合并(别名识别)+事件排序+伏笔链构建+关系图谱+力量体系推导+主角档案初始化
  ↓
⑤ 入库: 大纲树+角色+事件(分S/A/B级)+伏笔+物品+势力+时间线+状态档案
```

## 耗时估算
| 阶段 | 10万字 | 50万字 | 100万字 |
|------|--------|--------|---------|
| 预处理 | 1-2s | 3-5s | 5-10s |
| 边界识别 | 3-5s | 10-15s | 20-30s |
| 逐章解析(LLM) | 2-5min | 10-20min | 20-40min |
| 全局蒸馏 | 10-20s | 30-60s | 1-2min |
| 入库 | 2-5s | 5-10s | 10-15s |

## 角色识别四步
1. **NER**: 人名识别+称呼识别+代词消解
2. **属性推断**: 从上下文/对话/称呼推断性别/身份/关系
3. **跨章合并**: "苏月"="月儿"="那少女" → 编辑距离<2融合
4. **重要性评分**: 出场频率+对话量+主线影响+角色关联度 → 自动分配主角/配角/反派/龙套

## 事件重要性评分
```python
score = 事件类型基础分(突破20/战斗10/获得12/失去15/信息18/日常2)
      + 主角在场 +10
      + 反派在场 +5
      + 篇幅占比 × 20
      + 后续被提及 +15
      + 情感强度 × 5
# >=35→S, >=20→A, else→B
```

## 拆书 vs 手动建大纲
| | 拆书 | 手动 |
|------|------|------|
| 输入 | 已有完整正文 | 只有构思 |
| 输出 | 大纲+正文+完整结构化数据 | 只有大纲结构 |
| 速度 | 10万字3-6分钟 | 慢 |
| 精度 | 自动，需人工复核 | 完全可控 |
| 适用 | 有存稿/旧作/他人作品 | 全新创作 |

## 拆书后联动
- **续写**: AI理解全文设定，精准续写后续章节
- **改写**: 改写某章时自动检测前后章是否需要适配
- **分析**: 查询角色出场频率/伏笔回收/时间线一致性
- **改编**: 人称转换/时间线重组/基于原世界观写新故事
