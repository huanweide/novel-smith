# 内部工作记录

这个目录放的是**开发过程文档**，不是产品文档。

**访客不需要看这里。** 想了解项目请看根目录的 [`README.md`](../../README.md)；
想了解架构请看 [`docs/ARCHITECTURE.md`](../ARCHITECTURE.md)。

## 为什么这些文件不在根目录

根目录是仓库的门面——陌生人点进来第一眼看到的就是它。
如果前几个文件是「更新报告」「调研计划」「修复方案」，
他看到的是作者的草稿纸，而不是一个能用的产品。

判断标准很简单：

| 放这里 | 放根目录 |
| --- | --- |
| 给自己看的过程记录 | 给访客看的产品说明 |
| 有具体日期的一次性计划 | 长期有效的约定 |
| 内部台账、真身路径 | README / CHANGELOG / 贡献指南 |

## 文件说明

- `agent.md` —— 开发台账。含项目真身路径、GitHub 现状、版本历史。**改代码前先看它第一节**（留意旧镜像路径，别在上面改）。
- `更新报告.md` —— 面向已熟悉项目的人的变更说明（大白话版，与 `CHANGELOG.md` 的技术记录互补）。
- `FIX-PLAN.md` —— 修复方案与排期。
- `*-2026-MM-DD.md` —— 各次调研/优化的一次性计划与报告，按日期归档。
