## 三、存储：零迁移「信封」

`saga.causality`（`Json?`）历史上是**裸数组**。升级为兼容三种形态的信封：

```jsonc
[
  { /* 老存档：裸数组 = 因果种子 */ }
]
// 或
{ "causality": [ /* 种子 */ ], "narrative": { /* 叙事账本 */ } }
```

- `causalityOnly()` / `parseExtensions()` **天然兼容**：只读 `causality` 键，忽略未知键 → 老存档与 session 三件套路径零改动。
- **必须改一处**：`game-engine.ts:858` 原本 `data:{ causality: settledSeeds }` 会整列覆盖、冲掉 `narrative`。改为「读旧信封 → 合并本轮账本 → 写回」，顺便修好「非因果变化轮不写 saga」导致的跨章种子丢失缺口。
- 不新增列、不跑 db push、不动 `@@unique` —— 零迁移。

账本体量封顶（提示词有预算）：故事线 12 / 单线事件 60 / 伏笔 40 / 世界卡 60 / 编年 30。

## 四、协同链路（本次真正的新东西）

引擎每轮的**真实产出**（不编造）：`parsed.narrative` / `newEntities` / 入库 `itemChanges` / `titles` / `relationChanges` / 种下的因 / 兑现的果 / 轮次与章序。

```
                      ┌→ 伏笔机：种因=登记 pending；正文种子命中=推进 fulfilled/partial
每轮真实信号 → syncRound ┼→ 故事线：大事自动采纳为 MILESTONE/EVENT（去重）；主线完结回填要素
                      ├→ 世界卡：新实体按 15 类自动归类（待审）；物品=item 类
                      ├→ 世界线：章序推进记一条编年；6 阶段进度算出来
                      └→ 发现提示：逐条变右侧浮体（不同颜色、错开上浮、不用点确定）
```

反向协同（让 AI 也知道，不只是玩家看得见）：`buildNarrativeContext()` 把活跃故事线时间轴、待收伏笔、已确认世界卡、当前阶段拼进提示词 —— 抄 `formatStorylines` 的口径。

## 七、世界意志（用户 2026-11-14 终审决策：**不另设系统**）

> 用户口径：「世界意志只要提示词推进的时候根据情况来就好，不需要设置。」

- **结论**：不在游戏本里造一个独立的「世界意志」模块 / 表 / 状态机。
- **理由（R/C/N）**：
  - R 合理：开放世界要的是「世界自己会往前走」，这本来就该**从已发生的事里涌现**，不该是作者预先写死的一条线。
  - C 正确：现有 `buildNarrativeContext()` 每轮已把「当前阶段 + 活跃故事线时间轴 + 待收伏笔 + 已确认世界卡 + 跨章编年」注入提示词——AI 手里的信息足够「按情况推进世界意志」，不缺输入。
  - N 必要：再造一条独立意志线 = 又一份真相 + 又要同步 + 又可能和故事线打架；能不加就不加（maxloop N 闸门）。
- **落到哪**：完全交给提示词推进。引擎每轮把真实信号喂进 `syncRound` 出账本、`buildNarrativeContext` 出上下文，AI 基于这两者「看情况」推动世界意志——**代码零新增**。
- **可验证**：本决策为"不加"，验证方式是「grep 全仓无 worldWill/世界意志 独立表或字段」（已核实零命中），以及提示词上下文已含阶段/故事线/伏笔/世界卡/编年五项。
