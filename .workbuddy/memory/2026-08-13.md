## round-22 v2.0.18 推送收尾（2026-08-13 续，部署阻塞解除）

### 阻塞背景
- v2.0.18（commit `5878d13`，10 文件 +326/-49）代码/单测/门禁/版本号全部就绪并已本地 commit，但 round-22 当时 `git push ghssh main`（SSH-over-代理 7897 → ssh.github.com:443 隧道）失败：`Connection closed by UNKNOWN port 65535`。
- 当时诊断：curl 探测所有候选代理端口（7890-7899/1080/8080）的 HTTP 与 SOCKS5 模式到 `https://ssh.github.com:443` 全 `http_code=000`；无 proxy 环境变量 → 判定代理环境变化、无法通达 GitHub，v2.0.18 滞留本地。

### 解除（本轮）
- **诊断纠偏**：用 bash `/dev/tcp` 重扫，发现 7897 其实 LISTEN（之前 PowerShell `Test-NetConnection ... 2>$null` 因 `$null` 在 bash 下非语法被误判 DOWN）；且**直连 `ssh.github.com:443` 与 `github.com:22` 端口均 OK** → 根本无需代理隧道，可直接 SSH 直连。
- **改用 SSH 直连推送**：`git remote add ghssh git@github.com:huanweide/novel-forge.git`，`GIT_SSH_COMMAND="ssh -i $HOME/.ssh/id_ed25519_huanweide -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -o ConnectTimeout=20" git push ghssh main` → 成功 `251fb17..5878d13 main -> main`（exit 0）。
- 推送后 `git remote remove ghssh`，origin 保持 `https://github.com/huanweide/novel-forge.git`。

### 方法论更新（重要，未来复用）
- **HTTPS 通道 TLS 直连失败**：`git fetch origin` 报 `TLS connect error: unexpected eof while reading`；但 **SSH 22 端口直连正常**。说明当前环境 GitHub 仅放行 22/443 的 SSH 握手，HTTPS 直连被中间设备截断。
- **未来推送优先用直连 SSH**（不再依赖代理隧道）：`GIT_SSH_COMMAND` 包装 `ssh -i ~/.ssh/id_ed25519_huanweide` 直连 `git@github.com:huanweide/novel-forge.git`（临时 ghssh remote 或改 origin 为 ssh 均可），push 完恢复 https origin。代理隧道 7897 现在不稳定，不可作为默认路径。
