## novel-forge 定位澄清 + 自检 banner 黑话缺陷诊断（瑞宝宝反馈）

### 项目定位（瑞宝宝明确）
- novel-forge 是「本地部署」项目：用户在自有机器 `docker compose up` 起 Postgres + 填 AI Key 跑。DB 与 AI Key 是部署者自备，自检 banner 提示「去设置页填 Key」对部署者是合理指引，不是 bug。
- 瑞宝宝本机 DB 已配好（故不报 DB 未连接）；截图里「数据库未连接」来自沙箱 3002 服务（沙箱无 DATABASE_URL），与本机无关，不矛盾。

### 真缺陷：AI 项黑话（已确诊根因）
- 现象：自检 banner 的 AI 项显示「服务器内部错误，请查看日志」黑话。
- 根因：`src/app/api/health/route.ts` 对 `getSettings()` 抛的清晰中文「LLM API Key 未配置——请在设置页面填入 Key，或在 .env 中设置 LLM_API_KEY」调用 `classifyError`；而 `src/lib/api-error.ts` 默认分支（108–117 行）只认 Prisma 错 / 网络错，其余一律兜底成「服务器内部错误，请查看日志」，把友好文案吞了。`getSettings` 本已写人话，被错误分类器强行黑话化。
- 底层：本机 DB 连着但 AI Key 没配 → getSettings 回退环境变量也空 → 抛「LLM API Key 未配置」→ 被 classifyError 黑话化。

### 待修方案（已执行 → v3.1.25）
- 给 `classifyError` 默认分支加「配置类友好错误」分支：当 `err.message` 已是可读中文业务提示（含「未配置/未填写/请」等关键词）直接透传 error，不再显示「服务器内部错误」。零风险（透传的是自写中文，不泄露 SQL/路径）。
- 修复后需走六处版本 bump + tsc + vitest + commit/push + 3002 验证闭环。

### 用户本机消除 AI 项实操
- 去 ⚙️ 设置页填 Key（提供商 deepseek + Key + 模型 deepseek-v4-flash）；或 `.env` 设 LLM_API_KEY/LLM_PROVIDER/LLM_MODEL（范本见 .env.example）。
